§ 03

Chat Request Lifecycle

What chatHandler in cmd/gateway/main.go does with one /v1/chat/completions or /v1/completions request. A block returns HTTP 400 with code content_filter. Every request gets one audit row (step 9).

1
Key, Rate Limit, Body Middleware
The API key resolves to an organization (and optionally a project). The key's rate limit is checked. The body is decoded with exact numbers; trailing data or a non-object body is refused.
key missing / unknown→HTTP 401
rate limit exceeded→HTTP 429
invalid body→HTTP 400
2
Org Scan Settings Gateway
The org's guard_settings are read from PostgreSQL and override the gateway's SCAN_ROLES and SPOTLIGHT defaults (INDIRECT_BLOCK_THRESHOLD is gateway-wide). They decide which roles are classified. By default: user turns, tool results and tool descriptions. System messages and earlier assistant tool-call arguments can be switched on; they are classified but forwarded unchanged.
settings cannot be read→HTTP 503, fail closed
3
L0 Sanitizer internal/sanitizer
User and tool text is replaced with its sanitized form. Steps 2–6 repeat until the text stops changing (at most 8 passes), because decoding an HTML entity can bring back something an earlier step removed. Content of a type that cannot be scanned (token arrays, non-string parts, keys that differ from a guarded key only in case) is refused.
① UTF-8 validate ② NFKC ③ strip default-ignorable · tag · bidi · variation selectors ④ strip ANSI escapes ⑤ strip C0/C1 controls ⑥ HTML strip (bluemonday) + entity unescape ⑥b remove spoofed marker tokens ⑦ homoglyph signal (mixed scripts in a word)
Anomaly score: tag chars +0.6 · bidi +0.3 · ANSI +0.2 · homoglyph +0.3 · spoofed marker +0.3, capped at 1.0
anomaly.score ≥ 0.6→HTTP 400 content_filter
invalid UTF-8 / too many encoding layers→HTTP 422
4
Injection Detector internal/inference
User text (and system / tool-call text when enabled) is joined and scored as the direct score. Each tool result and each tool definition is scored on its own as indirect, with a category hint (indirect_injection, tool_poisoning); tool descriptions also get MCP poisoning signals. Long text is split into overlapping windows and the worst window counts. Layers are described in § 04.
injection.score injection.category scores.l1 · l2 · l3 indirect.score indirect.source injection.source_role
detector error→HTTP 503, fail closed
too long to scan→HTTP 413
5
Fixed Thresholds Gateway
Constants in cmd/gateway/main.go. They run before policies, so no policy can allow what they block. The indirect threshold can be lowered but never set above 0.85.
direct score ≥ 0.85→HTTP 400 content_filter
indirect.score ≥ INDIRECT_BLOCK_THRESHOLD (default 0.85)→HTTP 400 content_filter
both below→continue
6
Spotlighting internal/indirect
Optional. With SPOTLIGHT=delimit or datamark (or the org setting), tool results are marked as untrusted data and a note explaining the marking is added to the system prompt. Off by default.
off delimit datamark
7
CEL Policies internal/policy
The org's enabled policies are loaded from PostgreSQL: project policies first, then org-wide ones, oldest first. Rules are evaluated in order; the first matching allow or block decides, a matching log rule is recorded and evaluation continues. No match means allow. Each rule and each request has a CEL cost limit. Details in § 05.
block rule matches→HTTP 400 content_filter
load / compile / evaluate error, cost limit, stale redact or route rule→HTTP 503, nothing sent upstream
allow, log only, or no match→continue
8
Upstream and Output Guard internal/proxy · internal/outputguard
The sanitized body goes to the OpenAI-compatible URL in UPSTREAM_LLM_URL. When that is empty, the gateway returns a stub answer instead. If the client hangs up, the upstream request is cancelled. The answer then passes the output guard (on by default, OUTPUT_* variables): images and links to hosts not on OUTPUT_LINK_ALLOWLIST are removed; email, Vietnamese phone, CCCD and card numbers (and IPv4 if enabled) become [REDACTED:type]; with OUTPUT_CANARY=block|redact a per-request canary is placed in the system prompt and caught if the model repeats it. Message content, reasoning fields and tool-call arguments are all guarded. Streams hold back a 256-character window per choice so a pattern split across chunks is still caught.
images · links email · phone · cccd · card · ipv4 canary reasoning: guard | drop
9
Audit Row PostgreSQL · requests
One row per request, whatever the outcome. Request and response bodies are stored as SHA-256 and byte length only, unless content storage is enabled (AUDIT_STORE_CONTENT or the org setting). pii_entities holds output guard counts as output:<type>=<n>, never the content. The control plane lists these rows and deletes old ones with its retention job.
action: allow · block · error · output_leak rule_id injection_score injection_label anomaly_score had_tag_chars · had_bidi pii_entities request_sha256 · request_bytes response_sha256 · response_bytes latency_ms · created_at
§ 04

Detection Layers

L1 always runs. L2 and L3 need a gateway built with -tags onnx (the Docker image is) and the model files under MODEL_DIR; without them the gateway runs on L1 alone, unless DETECTOR_REQUIRE_ML=true. Each layer's raw score is Platt-calibrated; the calibrated scores are combined by logistic regression (DETECTOR_FUSION=logreg, the default) or by taking the maximum (max). If a weighted layer did not run for a request, that request falls back to the maximum.

L1 · Rules on a skeleton

internal/inference/rules · internal/inference/skeleton
Input
A lossy skeleton of the sanitized text, used only for matching: Vietnamese diacritics removed, confusables folded to Latin, leetspeak folded, spelled-out letters joined, repeated letters squeezed, Vietnamese teencode expanded
Rules
Weighted phrase sequences in one sentence (English and Vietnamese), plus structural regexes on the original text. Single keywords add only a small score
Suppressors
Discussion of attacks, quoted examples, string literals in code, negation
Output
Score, top category and the ids of the rules that fired

L2 · Classifier  ·  L3 · Similarity

internal/inference/ml · ONNX Runtime via internal/onnx
L2 model
guardspec-classifier-v1, our fine-tune of intfloat/multilingual-e5-small with an attack-category head. Risk = 1 − p(benign). Not on Hugging Face: copied into models/local/
L3 model
multilingual-e5-small embeddings compared with attack and benign exemplars, plus the org's own exemplars (managed in the control plane, read from PostgreSQL)
Cascade
Optional (DETECTOR_CASCADE=true): L2 and L3 are skipped when L1's calibrated score is already decisive. Otherwise L1 runs first, then L2 and L3 in parallel
Layers
DETECTOR_LAYERS, default l1,l2,l3
§ 05

Policies

Policies are stored per org (optionally per project) as a JSON condition tree. The control plane validates and compiles each rule to CEL when it is saved; the gateway evaluates them in step 7. Policies run after the fixed thresholds, so they can only make blocking stricter.

Rule model

internal/policy/policy.go
Condition
Clauses of field, operator (== != > >= < <= contains in) and value, combined with and / or
Actions
allow, block, log. redact and route are refused by the control plane; a stored rule with one fails closed (503)
Order
Project policies, then org-wide; inside a policy, rule order. First matching allow or block wins
Limits
CEL cost limit per rule and a total budget per request; exceeding either fails closed
Example — block indirect injection from tool results
{
  "name": "block-tool-injection",
  "condition": {
    "combinator": "and",
    "rules": [
      { "field": "indirect.source", "operator": "==", "value": "tool" },
      { "field": "indirect.score",  "operator": ">=", "value": 0.6 }
    ]
  },
  "action": "block"
}

Variables

What a condition can read
request.*
model, tenant_id, tokens
injection.*
score, label, category, source_role
scores.*
l1, l2, l3 (calibrated; −1 when the layer did not run)
indirect.*
score, source (tool, document, tool_description)
anomaly.*
score, has_tag_chars, has_bidi
mcp.*
is_tool_response
removed
toxicity.score, pii.entities, topic.categories: no detector produces them. New rules naming them are refused; stored ones see zero or empty
§ 06

Control Plane API

REST API under /v1 (cmd/control-plane/main.go). Login returns a JWT; org routes check the caller's role: owner, admin, member or viewer. There is no UI; clients call the API directly.

AreaRoutesNotes
Auth
 POST /v1/auth/login, POST /v1/invites/accept Both rate limited.
Organizations
 /v1/organizations, /:orgId, /:orgId/guard-settings Guard settings: scanned roles, spotlight mode. Read by the gateway in step 2.
API keys
 /:orgId/api-keys Create, update, revoke. Admin only.
Projects
 /:orgId/projects Scope for project policies.
Policies
 /:orgId/policies, POST /v1/cel/validate JSON condition tree compiled to CEL on save.
Audit
 GET /:orgId/requests Lists audit rows. A background job deletes rows past the retention period.
Exemplars
 /:orgId/exemplars The org's own L3 exemplars, stored only in the database.
Invites
 /:orgId/invites (also /orgs/:orgId) Invite users to an org with a role.

Not Built

Earlier versions of this page described these. None of them exist in the code.

ItemStatusNotes

 ○ Not built One upstream per gateway. The route action is refused.
Input-side toxicity, PII, topic detectors
 ○ Not built Their runner slots return neutral stubs and they are not policy inputs. PII redaction exists only on the output side (step 8).

 ○ Not built No Python service, no /predict, no Triton or GPU serving. Models run in the gateway via ONNX Runtime on CPU.
